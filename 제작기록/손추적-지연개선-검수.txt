2026-11-12 — 손 추적 지연 개선 / 도시 전용 음원

변경
- tracking-worker.js: 실제 손/얼굴 분석을 별도 작업에서 실행. GPU 우선, 같은 작업 안의 CPU 대체 경로.
- tracking-client.mjs: 이미지1장만 처리, 작업 중에는 새 요청을 쌓지 않음.
  화면/관객 변경 전 결과 무시,160ms 초과 결과 무시, 이미지는 처리 직후 해제.
- tracking-schedule.mjs: 손30Hz 목표, 매장 얼굴5Hz/도시 얼굴10Hz.
- pose.mjs/motion.mjs: 손 이동 속도에 따라 카메라 모드의 따라오기 지연을 줄임.
  C자 잡기 기준/펼쳐 놓기/소실 유예와 관객 선택 기준 유지.
- 가이드에 실제 수신한 손 분석 결과 횟수 표시. 검출 성공률이나 화면fps를 의미하지 않음.
- audio.js/index.html: 처음 후렴은0.6배속, 도시 도착 시 별도 Jingle Bells in the City.mp3 재생.
  도시곡은 원속도/원음높이, 원래 흔들기곡은 감쇠 후 정지. 엔딩은 양쪽 곡을 감쇠 후 정지.

자동 검증
- check-hand-tracking: 빠른 C자 이동, 간헐적 인식 소실, 입력 속도,
  따라오기 지연, 얼굴/손 처리 간격, 관객 없음/보정 중 손 제어 금지 통과.
- 입력프레임30fps: 매장 손25Hz/얼굴5Hz, 도시 손20Hz/얼굴10Hz.
- 입력프레임60fps: 손30Hz, 얼굴 매장5Hz/도시10Hz.
  위 수치는 실제 추론 시간이 없는 일정 모의 검사이며 기기 성능 수치가 아님.
- 합성 빠른 이동에서 새 카메라 보정의 위치 오차 합계는 이전 방식의 약55%.
- 배포9b94778의 HeldPose와 새 마우스 모드를600프레임 비교:
  위치/속도/회전/놓기 모두 완전 일치.
- check-tracking-client: 이미지 대기열 없음, 오래된 결과/세션 결과 거부,
  캡처 실패 복구, 작업 종료 통과.
- 기존 motion/grip/audience/snow-wish 및 carol 검사 통과.

실제 브라우저의 모델 검사
- verification/worker-preview.html에서 카메라 권한 없이 빈640×480 캔버스를 입력.
- 손/얼굴 모두 GPU 초기화 성공. 최초 추론 사전 준비 후12개 분석 결과 수신, 버림0.
- 분석 중 화면갱신22회, 가장 긴 프레임 간격17ms, 마지막 결과 도착 지연 약7.7ms.
- 오류 로그 없음. 이는 빈 영상과 해당 로컬 브라우저의 관찰치다.
  실제 손 인식률, 실제 카메라 영상의 지연, 전시장 전체 렌더 성능으로 해석하지 않는다.

실제 브라우저의 도시 음악 검사
- 음소거 검증 탭에서 자동 흔들기 → 도시 도착 → 눈 받기 → 엔딩 흐름 확인.
- 도시에서는 jingle-bells-city.mp3가 준비 상태4, 재생 중,1배속이며 기존곡은 정지.
- 엔딩 감쇠 후 두 음원 모두 정지, 오디오 모드 ending 확인. 브라우저 오류 로그 없음.
- 소리가 겹치지 않도록 음소거로 검사했으므로 실제 청감은 확인하지 않음.

미확인
- 실제 사람이 C자를 유지하며 빠르게 움직일 때의 카메라 체감.
- 여러 관객이 겹치거나 손이 화면 밖으로 나갔다 돌아올 때의 실사용.
- 워커 CPU 대체 경로의 실제 기기 성능.
- 음원 전환/음색 청감은 사용자 확인 필요.

확인 방법
http://127.0.0.1:8877/ 새로고침 → 카메라로 시작 → C자로 잡고 좌우/위아래 이동.
손 모양 가이드와 손 분석 횟수, 실제 스노우볼의 따라오는 느낌을 함께 확인.
검수 후 사용자가 커밋·푸시·기존 GitHub Pages 배포를 요청함.
